# Диспетчеризация уборочной техники

Веб-платформа для построения маршрутов уборочных тракторов по дорожной сети
города. Приложение делит город на равномерную сетку клеток, позволяет вручную
назначить клетки тракторам и запускает Python-скрипт маршрутизации, который
собирает обязательные дорожные отрезки и формирует итоговый файл `routes_grid.kml`
для импорта в Яндекс Конструктор карт.

> 📌 **Перед запуском создайте файл `.env` с ключом Google Directions API.**
>
> ```bash
> cp .env.example .env  # создаст шаблон, если файла ещё нет
> echo "GOOGLE_API_KEY=ВАШ_КЛЮЧ" >> .env
> ```
>
> Файл `.env` автоматически подхватывают и веб-сервер, и скрипт
> `route_builder_grid_v7_1.py`, поэтому вручную экспортировать переменные не
> требуется.

## Возможности

* Интерактивная карта на Leaflet с отображением сетки клеток и легендой цветов.
* Синхронное редактирование распределения клеток между тракторами через
  WebSockets (Flask-SocketIO).
* Управление построением маршрутов из браузера с выводом пошагового лога.
* Генерация маршрутов длиной около 30 км для каждого трактора с учётом линий
  дорог из `RoadCity.kml`.
* Экспорт сетки клеток в `static/sectors.geojson` и маршрутов в `routes_grid.kml`.
* Поддержка Google Directions API для переездов между дорожными сегментами с
  деградационным режимом (прямые отрезки), если ключ отсутствует.
* Кнопка «🎲 Автораспределение» для мгновенного случайного назначения клеток
  тракторам при тестировании и стартовой подготовке.
* Автоматическая визуализация готовых маршрутов на карте сразу после расчёта.

## Требования

* Python 3.10+
* Установленные зависимости из `requirements.txt`:

  ```bash
  pip install -r requirements.txt
  ```

## Файлы входных данных

Разместите в корне проекта рядом с `server.py` следующие файлы:

* `GEO.kml` — границы города (один или несколько полигонов).
* `RoadCity.kml` — дорожная сеть, разбитая на отрезки (`LineString`).

Именно эти файлы используются при генерации сетки и построении маршрутов.

## Переменные окружения

| Переменная       | Назначение                                                               |
|------------------|-------------------------------------------------------------------------|
| `GOOGLE_API_KEY` | Ключ Google Directions API. При отсутствии переезды выполняются прямыми |
| `FLASK_SECRET`   | Секрет для сессий Flask (необязательно).                                |

Создайте файл `.env` в корне проекта (в той же папке, где находятся `server.py` и
`route_builder_grid_v7_1.py`) и заполните значения переменных. Оба Python-скрипта
автоматически подгружают этот файл при старте. Веб-сервер также перечитывает `.env`
при обращениях, поэтому изменения подхватываются без перезапуска.

## Быстрый старт

1. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

2. Подготовьте конфигурацию Google Directions:

   ```bash
   cp .env.example .env
   echo "GOOGLE_API_KEY=ВАШ_КЛЮЧ" >> .env  # по желанию
   ```

3. Поместите в корень проекта рядом с `server.py` файлы `GEO.kml` и
   `RoadCity.kml`.

4. Запустите сервер:

   ```bash
   python server.py
   ```

5. Откройте [http://127.0.0.1:5000](http://127.0.0.1:5000). При первом заходе
   сервер автоматически попытается сгенерировать `static/sectors.geojson`. Если
   входных файлов нет или они повреждены, в правой панели появится красный
   баннер «Ошибка сетки» с подсказкой.

6. Подберите параметры: выберите размер сетки в выпадающем списке и при
   необходимости нажмите «Применить параметры». Это перегенерирует сетку.
   Назначения клеток будут сброшены при смене размера.

7. Назначайте клетки тракторам. Выберите трактор, кликните по нужным ячейкам
   (они окрасятся в цвет трактора). Повторный клик снимает назначение. Все
   изменения синхронизируются между вкладками и сохраняются в `assignments.json`.
   Для быстрой проверки можно воспользоваться кнопкой «🎲 Автораспределение» —
   клетки будут случайно распределены между тракторами и тут же окрашены.

8. Нажмите «💾 Сохранить и построить», чтобы запустить `route_builder_grid_v7_1.py`.
   Прогресс расчёта отображается в логе. Пока расчёт идёт, кнопка построения
   блокируется у всех подключённых клиентов.

9. После успешного завершения активируется кнопка «⬇️ Скачать KML», а маршруты
   автоматически появятся на карте поверх сетки. Скачайте `routes_grid.kml` и
   импортируйте файл в Яндекс Конструктор карт.

Если баннер «Ошибка сетки» остаётся видимым, проверьте входные файлы и нажмите
«Применить параметры» (или выберите другой размер сетки), чтобы принудительно
перегенерировать GeoJSON. Пока ошибка не устранена, построение маршрутов
недоступно.

## Структура проекта

```
.
├── assignments.json          # Текущее распределение клеток (создаётся автоматически)
├── route_builder_grid_v7_1.py# Скрипт маршрутизации и генерации сетки
├── server.py                 # Flask + SocketIO веб-сервер
├── app_settings.json         # Сохранённые параметры (кол-во тракторов, сетка и др.)
├── static/
│   └── sectors.geojson       # GeoJSON с сеткой клеток
├── templates/
│   └── map.html              # Интерфейс карты на Leaflet
└── routes_grid.kml           # Итоговый KML (создаётся после построения)
```

## Типовой сценарий работы

1. Подготовьте входные файлы `GEO.kml` и `RoadCity.kml`.
2. Запустите сервер (`python server.py`). При первом обращении будет создана
   сетка `static/sectors.geojson`.
3. В правой панели доступны настройки: «Размер сетки», количество тракторов,
   целевая длина маршрута, режим Google Directions и координаты базы. При
   изменении сетки распределения очищаются автоматически.
4. В браузере назначьте клетки тракторам. Распределение сохраняется в
   `assignments.json` и синхронизируется между вкладками.
5. Нажмите «Сохранить и построить». В лог выводятся шаги: чтение входных файлов,
   построение сетки, распределение дорог, построение маршрутов.
6. После завершения расчёта скачайте `routes_grid.kml` и импортируйте в Яндекс
   Конструктор карт.

## Примечания

* Все ключевые параметры маршрутизации теперь доступны прямо в браузере: размер
  сетки, количество тракторов, целевая длина, режим Google Directions, координаты
  базы и центра карты. Изменения сохраняются в `app_settings.json` и применяются
  без перезапуска сервера.
* Карта по умолчанию центрирована на координатах 54.920031, 37.408090 (эти же
  значения используются для стартовой базы). При необходимости их можно
  переопределить в панели настроек перед запуском расчёта.
* При отсутствии Google Directions API переезды между дорожными сегментами
  выполняются прямыми линиями, что отмечается в логе и интерфейсе.
* Все сообщения о ходе выполнения доступны в веб-интерфейсе благодаря
  SocketIO. Лог также выводится в консоль, если запускать скрипт отдельно.
