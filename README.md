# AIroad Tractor Dispatcher

Полноценный веб-инструмент для диспетчеризации уборочной техники: разбивает город по GEO.kml, позволяет назначать клетки и дороги тракторам, строит маршруты с визуализацией в реальном времени и выгружает результат в `routes_grid.kml`.

## Структура проекта

```
project/
  server.py                 # Flask + Socket.IO сервер
  route_builder_grid_v7_1.py# CLI-скрипт маршрутизации
  route_builder/            # модульная логика построения
  static/                   # фронтенд (Leaflet + Socket.IO)
  templates/                # map.html
  data/                     # входные/выходные файлы (GEO, RoadCity, kml)
  cache/                    # кэш геокодера
  requirements.txt
  env.example
  app_settings.json
```

## Быстрый старт

1. Установите зависимости:
   ```bash
   cd project
   python -m venv .venv && source .venv/bin/activate  # опционально
   pip install -r requirements.txt
   ```
2. Скопируйте пример окружения и пропишите ключи:
   ```bash
   cp env.example .env
   # заполните GOOGLE_API_KEY и YANDEX_API_KEY (опционально)
   ```
3. Подготовьте входные данные в каталоге `project/data/`:
   - `GEO.kml` — границы города (полигон/мультиполигон);
   - `RoadCity.kml` — все дорожные сегменты.
4. Запустите сервер:
   ```bash
   python server.py
   ```
5. Откройте http://127.0.0.1:5000 — появится карта.
6. Настройте параметры (режим сетки/дорог, источник улиц, Advanced Optimization), при необходимости используйте «🔀 Авто-раздать смежные районы».
7. Нажмите «🧭 Построить маршруты». Во время маршрутизации:
   - панель показывает подсвеченный лог стадий (чтение, распределение, построение, экспорт, завершение);
   - вращающийся индикатор в углу отображает прогресс;
   - линии маршрутов рисуются на карте в реальном времени;
   - после завершения кнопка «⬇️ Скачать KML» активна, а карта автоматически добавляет итоговый слой.
8. Кнопка «♻️ Очистить маршруты» мгновенно убирает все линии с карты и удаляет текущий `routes_grid.kml`.

## Ключевые особенности

- **Живой прогресс:** сервер транслирует все этапы и геометрию маршрутов по мере построения (`route_step`), лог подсвечивается по типам сообщений.
- **Компактное автораспределение:** KMeans по клеткам или дорогам, продвинутая балансировка улиц с использованием обратного геокодинга Google/Yandex. Кластеры формируются смежными районами без «шахматки».
- **Гибкие настройки:** тумблеры режима (Grid / Road), источника названий улиц, Advanced Optimization, параметры сетки и траекторий.
- **Современный UI:** тёмная панель управления, живой индикатор прогресса, подсветка районов и всплывающие подсказки по тракторам.
- **Темы и адаптив:** переключатель светлой/тёмной темы, мобильное меню с гамбургером, лог со скроллом и toasts.
- **Кэширование и ретраи:** геокодер сохраняет результаты в `cache/streets_cache.json` и повторяет запросы при сбоях.
- **Экспорт:** маршруты формируются в `data/routes_grid.kml`, дополнительно создаётся `data/roads_colored.kml` при построении.

## Описание переменных окружения (`.env`)

| Переменная | Назначение |
|------------|------------|
| `FLASK_HOST`, `FLASK_PORT` | адрес и порт сервера |
| `SECRET_KEY` | секрет Flask |
| `GOOGLE_API_KEY` | ключ Google Directions + Geocoding |
| `YANDEX_API_KEY` | ключи Yandex Routing/Geocoder |
| `ROUTING_PROVIDER` | провайдер переездов между линиями (google/yandex) |
| `GOOGLE_MAX_WAYPOINTS` | ограничение точек для Directions (23 по умолчанию) |
| `REQUEST_PAUSE` | пауза между запросами к API |
| `SAMPLE_EVERY_M` | шаг дискретизации линий при live-визуализации |
| `STREET_SOURCE` | источник названий улиц (google/yandex) |
| `ADVANCED_OPTIMIZATION` | включение расширенной балансировки |
| `TARGET_KM_PER_TRACTOR` | целевая длина маршрута на трактор |

## Папка `data/`

- `GEO.kml`, `RoadCity.kml` — входные файлы (добавьте сами).
- `grid.geojson` — автогенерируемая сетка клеток.
- `assignments.json` — ручные назначения клеток.
- `roads_assignment.json` — назначения дорожных сегментов.
- `routes_grid.kml` — финальный результат для загрузки.
- `roads_colored.kml` — дороги, окрашенные по трактору.
- `street_summary.csv` — отчёт по улицам (advanced режим).

## Примеры GEO.kml и поведение при ошибках

Минимальный валидный `GEO.kml` может выглядеть так:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<kml xmlns="http://www.opengis.net/kml/2.2">
  <Placemark>
    <name>City boundary</name>
    <Polygon>
      <outerBoundaryIs>
        <LinearRing>
          <coordinates>
            37.400,54.915,0 37.430,54.915,0 37.430,54.935,0 37.400,54.935,0 37.400,54.915,0
          </coordinates>
        </LinearRing>
      </outerBoundaryIs>
    </Polygon>
  </Placemark>
</kml>
```

Допустимы варианты с `MultiGeometry`, `LinearRing` и даже замкнутым `LineString` — парсер автоматически преобразует их в полигоны. Если в файле нет ни одного замкнутого контура, сервер вернёт понятное сообщение вида:

```
GEO.kml не содержит полигонов. Найдено: Placemark: 3, LineString: 1. Фрагмент: ...
```

В этом случае сетка не генерируется (HTTP 409), а на фронтенде появляется баннер «Ошибка сетки». После исправления входного файла достаточно нажать «Сохранить сетку» — генерация произойдёт повторно.

## CLI-режим

Маршрутизатор можно запускать отдельно:
```bash
python route_builder_grid_v7_1.py \
  --geo data/GEO.kml \
  --roads data/RoadCity.kml \
  --roads-assignment data/roads_assignment.json \
  --output data/routes_grid.kml
```

CLI выводит прогресс и события `[ROUTE_STEP]`, `[ROUTE_DONE]`, которые сервер использует для live-визуализации.

## Диагностика

- Если нет `GEO.kml` или `RoadCity.kml` — в UI появится баннер и кнопка построения будет заблокирована.
- При отсутствии `GOOGLE_API_KEY` маршруты соединяются прямыми сегментами (лог содержит предупреждение).
- Все ошибки Flask и фонового процесса возвращаются как JSON и появляются в логе интерфейса.

Готово! Проект можно запускать «из коробки», визуализировать прогресс и сразу выгружать маршруты.
